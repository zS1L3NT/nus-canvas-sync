# Server setup

These steps run the project on an always-on Debian server: Canvas is fetched on a schedule, and the vault is served over WebDAV so the Remotely Save plugin can sync it to Obsidian on a phone or computer. Each part can be turned off under `server` in `config.json`. Commands marked **old machine** run where the project ran before; the rest run on the server.

## 1. Prepare the server

```sh
sudo apt install curl unzip git util-linux rsync
git clone <repository URL> ~/nus-canvas-sync
cd ~/nus-canvas-sync
deploy/setup.sh
exec $SHELL -l    # picks up ~/.bun/bin and ~/.local/bin
```

`deploy/setup.sh` installs bun and canvas-cli into your home directory without sudo, installs the dependencies, and creates `config.json` from `config.example.json` if there is none. Rerun it any time.

Document extraction uses npm packages for PDF, Word, RTF, OpenDocument, Office archives, and image OCR. Bun installs them with the project dependencies, including local English OCR data; no `textutil`, `pdftotext`, `tesseract` executable, or extraction-time `unzip` is needed. The setup script still uses `unzip` to install server binaries.

## 2. Configure

`config.json` is gitignored because it holds personal details such as course IDs and paths. Set your courses in it, and choose the server parts under `server`:

| Setting | Effect | `null` or `false` |
|---|---|---|
| `fetchSchedule` | systemd `OnCalendar` value for the fetch timer, such as `hourly` or `*:0/30`, without spaces | no timer; fetch manually |
| `webdavPort` | serves the vault over WebDAV on `127.0.0.1:<port>` | no WebDAV server |
| `tunnel` | publishes the WebDAV server through a Cloudflare tunnel | no tunnel; reach the port another way, such as a VPN |

If you are moving an existing setup, copy the files git does not carry so the server continues where the old machine left off rather than starting a new baseline. **Old machine:**

```sh
rsync -a config.json STYLE.md known-content.json raw <server>:nus-canvas-sync/
```

## 3. Log in to Canvas

In Canvas, go to Account → Settings → New Access Token, and create one for the server. Then:

```sh
canvas auth token set nus --url https://canvas.nus.edu.sg   # paste the token at the prompt
bun run doctor
```

## 4. Create the Cloudflare tunnel (if `tunnel` is on)

In the Cloudflare dashboard, open Zero Trust → Networks → Tunnels and create a tunnel:

1. Connector type **Cloudflared**, any name.
2. On the install step, copy only the token: the long string after `--token` in the shown commands. Do not run those commands; the setup script runs cloudflared itself.
3. Add a public hostname on a domain you manage in Cloudflare, with service type **HTTP** and URL `localhost:<webdavPort>`.

Keep the hostname out of the repository. It belongs only in the Cloudflare dashboard and your Remotely Save settings.

## 5. Start the services

```sh
deploy/setup.sh --production
```

It asks once for what the enabled parts need:

- a **WebDAV username and password** for Remotely Save. Use 20 or more letters, digits, `.`, `_` or `-`, generated by a password manager. With the tunnel on, this password is all that protects the public address.
- the **Cloudflare tunnel token** from step 4.

These are stored with mode 600 in `~/.config/nus-canvas-sync/`, outside the repository. The script then installs rclone and cloudflared as needed and enables the chosen systemd user units: `canvas-fetch.timer`, `canvas-webdav` and `canvas-tunnel`. Turning a setting off and rerunning the script disables its unit. If it asks you to, run `sudo loginctl enable-linger $USER` so the units keep running after you log out and across reboots.

Run the first fetch now and watch it:

```sh
systemctl --user start canvas-fetch
journalctl --user -u canvas-fetch -f
```

When it finishes, open `https://<tunnel hostname>/Canvas/` in a browser. It should ask for the WebDAV password and then list `Home.md` and the course folders. WebDAV exposes the vault under `/Canvas/`, which is the folder Remotely Save expects for a vault named `Canvas`; the files stay in `vaultDirectory` on disk.

## 6. Connect Obsidian

On each device, create a **new, empty vault named `Canvas`** (on iPhone, turn off "Store in iCloud"). The name matters: report links open `obsidian://open?vault=Canvas`. Do not reuse an existing synced copy of the vault, or Remotely Save may upload stale files.

Then, in that vault:

1. Settings → Community plugins → turn on community plugins → Browse → install and enable **Remotely Save**.
2. Remotely Save settings → Remote service **WebDAV**: the `https://` address of your tunnel hostname, the username and password from step 5, auth type **basic**. Use the hostname root as the address, without `/Canvas/`; the plugin adds that folder automatically. Leave the remote base directory unset or set it to `Canvas`. Tap **Check connectivity**.
3. Auto sync: turn on **sync on startup** (a few seconds' delay) and a schedule such as every 10 minutes. Optionally turn on sync on save for your own notes.
4. Run the first sync on Wi-Fi; it downloads the whole vault.

The server is the source of the generated notes: anything you change in a generated note is overwritten at the next fetch. Your own notes sync both ways and are never deleted by a fetch. Cloudflare's free plan rejects uploads over 100 MB.

Remotely Save aborts any sync that would modify more than 50% of the vault ("Abort sync if modification above percentage"). An update that changes how every note is written trips it, and the device stops syncing silently. Run one manual sync on each device and confirm it. Leave the limit as it is.

## 7. Use it

SSH into the server, then:

```sh
cd ~/nus-canvas-sync
claude
```

Ask for a **Canvas report** or run `/canvas-report`. In T3 Code with Codex, open the production checkout and invoke `$canvas-report`; the shared skill is in `.agents/skills/canvas-report/SKILL.md`. Connect Notion and Google Calendar in the agent you use. For Claude Code, log in to the claude.ai account with those connectors and check with `/mcp`; those account connectors do not carry over to other agents.

Useful checks:

```sh
systemctl --user list-timers canvas-fetch.timer   # next and last fetch
journalctl --user -u canvas-fetch -n 50           # last fetch output
systemctl --user status canvas-webdav canvas-tunnel
```

## Tearing down

```sh
deploy/teardown.sh                      # stop and remove the systemd units
deploy/teardown.sh --secrets --tools    # also delete stored secrets, log canvas-cli out, delete rclone and cloudflared
```

Teardown never deletes `raw/`, the vault or `config.json`, and leaves bun and canvas-cli installed. After `--secrets`, also revoke the Canvas access token in Canvas and delete the tunnel in the Cloudflare dashboard. To bring everything back, run `deploy/setup.sh --production` again.

## Optional: fewer sudo prompts for agents

Claude Code and Codex stop at sudo because they cannot type your password. To let them install packages unattended, add a sudoers drop-in with `sudo visudo -f /etc/sudoers.d/agents`:

```
<your user> ALL=(root) NOPASSWD: /usr/bin/apt, /usr/bin/apt-get
```

Any agent on the server can then become root, because packages run their install scripts as root. Only do this on a server you alone use. This project itself never needs it.
